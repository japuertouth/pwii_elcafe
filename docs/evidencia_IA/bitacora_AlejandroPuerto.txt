RESPUESTA DE LA IA:
Para centralizar la comunicación entre el frontend y la API de Express manteniendo una experiencia de usuario robusta y segura, implementa la siguiente arquitectura:

1. Ajuste de CORS en el Backend (backend/src/app.js):
Configura el middleware cors() antes de definir las rutas /api:

  app.use(cors({
    origin: process.env.FRONTEND_URL || '*',
    methods: ['GET', 'POST', 'PUT', 'PATCH', 'DELETE', 'OPTIONS'],
    allowedHeaders: ['Content-Type', 'Authorization']
  }));

Esto permite que el navegador realice peticiones preflight (OPTIONS) y envíe el encabezado Authorization sin bloqueos.

2. Cliente HTTP Centralizado (public/js/comun.js):
Crea una función asíncrona solicitudApi(endpoint, opciones = {}) que encapsule la lógica de fetch, la inyección del token y el manejo de errores HTTP:

  async function solicitudApi(endpoint, opciones = {}) {
    const token = localStorage.getItem('token');
    const config = {
      ...opciones,
      headers: {
        'Content-Type': 'application/json',
        ...(token ? { Authorization: `Bearer ${token}` } : {}),
        ...(opciones.headers || {})
      }
    };

    if (config.body && typeof config.body === 'object') {
      config.body = JSON.stringify(config.body);
    }

    const res = await fetch(endpoint, config);

    if (res.status === 401) {
      localStorage.removeItem('token');
      localStorage.removeItem('usuario');
      if (!window.location.pathname.endsWith('cuenta.html')) {
        window.location.href = '/cuenta.html?sesion=expirada';
      }
      throw new Error('Tu sesión ha expirado. Inicia sesión nuevamente.');
    }

    const datos = await res.json().catch(() => ({}));
    if (!res.ok) {
      throw new Error(datos.mensaje || datos.error || `Error del servidor (${res.status})`);
    }

    return datos;
  }

3. Actualización Dinámica de la Barra de Navegación (public/js/comun.js):
Al cargar cualquier página (DOMContentLoaded), verifica si existe localStorage.getItem('token'). Si el usuario está autenticado, muestra su nombre, habilita el enlace al panel de administración (si su rol es admin) y renderiza el botón funcional de Cerrar Sesión que ejecuta localStorage.removeItem('token'), limpia los datos de sesión y redirige a cuenta.html.

RESPUESTA DE LA IA:
Aquí tienes la integración completa del flujo de autenticación en el cliente:

1. Manejo de Formularios de Login y Registro (public/js/cuenta.js):
- Intercepta el evento submit con e.preventDefault().
- Activa el estado de carga (boton.disabled = true; boton.textContent = 'Verificando...') dentro de un bloque try / catch / finally.
- En el try, envía los datos del formulario mediante await solicitudApi('/api/auth/login', { method: 'POST', body: { correo, password } }).
- Al recibir el token, guarda localStorage.setItem('token', respuesta.token) y localStorage.setItem('usuario', JSON.stringify(respuesta.usuario)).
- En el catch(err), muestra el mensaje de error devuelto por la API dentro de un contenedor de alerta accesible (role="alert") sin recargar la página.

2. Guardia de Protección de Vistas (public/js/comun.js):
- Expone verificarAccesoPrivado(requiereAdmin = false): si !localStorage.getItem('token'), redirige inmediatamente con window.location.replace('/cuenta.html'). Si requiereAdmin es true y el rol almacenado no es administrador, redirige a /index.html. La validación real de seguridad se mantiene respaldada en cada petición por auth.middleware.js y rol.middleware.js en Express.

3. Restablecimiento de Contraseña (public/js/restablecer.js):
- Lee el parámetro ?token=... de la URL con URLSearchParams. Si existe, muestra el formulario para ingresar la nueva contraseña y hace POST al endpoint de confirmación; si no existe, muestra el formulario para solicitar el envío del correo de recuperación.
